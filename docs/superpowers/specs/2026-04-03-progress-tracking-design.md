# Progress Tracking System Design

**Date:** 2026-04-03  
**Status:** Approved  
**Scope:** claude-workflow plugin (`ParkerM2/create-claude-workflow`) + Claude-UI Electron app

---

## Overview

Two distinct tracking systems with clear separation of concerns:

- **System A** — Internal plugin state. Silent, ephemeral, never user-facing. `.current-context.json` is active across all three commands; the sentinel and gate files are `/agent-team` only.
- **System B** — User-facing progress. Persistent, editable, consumed by Claude-UI. Covers all three commands: `/deep-research`, `/new-plan`, `/agent-team`.

---

## System A — Internal Plugin State

Location: `.claude/` (project root)

```
.claude/
  .current-context.json     ← active ticket + phase (written by all 3 commands)
  .workflow-active           ← sentinel: enforcement guards on/off (agent-team only)
  .workflow-state/           ← gate files: preflight, plan, setup, wave-N, guardian
```

### `.current-context.json`

The routing key for `tracking-emitter.js`. Written at command start, updated as the run progresses, deleted at command end.

```json
{
  "ticket": "ES-101",
  "phase": "research|plan|agent-team",
  "runSlug": "001-auth-refactor"
}
```

`runSlug` is `null` during research and plan phases. Set by `wf-setup` once the sealed run folder is created.

### `.workflow-active` (sentinel)

Written by `wf-setup` (Step 3). Deleted by `wf-finalize` (Step 6). Used exclusively by `workflow-enforcer.js` to gate enforcement. Not used by `tracking-emitter.js`.

```json
{
  "ticket": "ES-101",
  "feature": "auth-refactor",
  "teamLeaderName": "team-lead",
  "startedAt": "2026-04-03T10:00:00Z",
  "mode": "strict"
}
```

### `.workflow-state/` gate files

Ephemeral stamp files that gate the 6-step `/agent-team` sequence. All deleted by `wf-finalize`.

```
preflight-complete.json
plan-complete.json
setup-complete.json
wave-<N>-spawned.json
wave-<N>-complete.json
all-waves-complete.json
guardian-passed.json
```

## System B — User-Facing Progress

Location: `./progress/` (project root)

### Directory Structure

```
./progress/
  ES-101/
    description.md                    ← requirements, context (optional, work tickets)
    events.jsonl                      ← full fidelity, all runs, append-only
    research/                         ← staging area: uncommitted research
      initial-audit.md
    tasks/
      001-auth-refactor/              ← sealed when agent-team starts
        research.md                   ← snapshot moved from research/
        plan.md
        task-1.md
        task-2.md
        report.md                     ← generated by wf-finalize
      002-follow-up/
        research.md
        plan.md
        task-1.md
        report.md
  research-auth-flow-2026-04-03/      ← no-ticket work: auto-slug from topic + date
    events.jsonl
    research/
      notes.md
  archive/                            ← user-controlled, organized however they want
    ES-098/
    sprint-march-2026/
      ES-077/
      ES-078/
```

### Ticket Lifecycle

1. User imports or creates ticket folder: `./progress/ES-101/`
2. Optional: add `description.md` with requirements
3. `/deep-research` → writes to `research/` staging area, appends to `events.jsonl`
4. `/new-plan` → uses staged research, writes `plan.md` to `research/`, appends to `events.jsonl`
5. `/agent-team` → `wf-setup` seals `tasks/001-slug/`, moves `research/` content in, runs agents
6. `wf-finalize` → writes `report.md`, cleans up System A
7. User archives ticket when done: `./progress/archive/`

### No-Ticket Work

When no ticket is specified, the command auto-generates a folder slug: `{topic-kebab-case}-{YYYY-MM-DD}`. The folder can be renamed or moved to a real ticket ID at any time without losing history (events.jsonl is self-contained).

## Event Schema (`events.jsonl`)

Full fidelity — every significant action logged. One JSON object per line, append-only.

```json
{
  "v": 1,
  "ts": "2026-04-03T10:23:45.123Z",
  "ticket": "ES-101",
  "run": "001-auth-refactor",
  "phase": "research|plan|agent-team",
  "seq": 42,
  "milestone": true,
  "agent": "schema-designer",
  "event": "agent.spawned",
  "data": {}
}
```

**Field notes:**
- `milestone: true` — the only flag the Electron app watches for UI re-renders
- `run` — null during research/plan phases; matches `tasks/NNN-slug/` folder name
- `agent` — null for team-lead and hook-emitted events
- `seq` — monotonic counter per ticket, never resets across runs

### Milestone Events (trigger UI re-render)

```
run.started           /agent-team kicked off
agent.spawned         coding or QA agent created
qa.passed             QA agent approved a task
qa.failed             QA agent rejected a task
branch.merged         work branch merged into feature branch
wave.complete         all tasks in a wave done
guardian.passed       codebase guardian approved
run.complete          wf-finalize finished cleanly
run.failed            run ended in error state
permission.required   agent needs user input (highest priority)
```

### Full-Fidelity Events (stored, silent — not milestone)

```
tool.use              every PostToolUse (tool name, duration, success)
message.sent          every SendMessage between agents
file.written          Edit/Write calls with file path
bash.executed         Bash calls (command truncated to 200 chars)
agent.idle            TeammateIdle fires
task.validated        TaskCompleted hook fires
proof.agent_spawned   agent spawned (merged from proof-ledger)
proof.branch_merged   branch merged (merged from proof-ledger)
proof.worktree_created
proof.worktree_removed
```

## Plugin Wiring Changes

### `tracking-emitter.js`
1. Read `.claude/.current-context.json` to resolve target `events.jsonl` path. If absent, exit 0 silently
2. Strip all `hookSpecificOutput` — write to file and exit 0, no visible output ever
3. Absorb `proof-ledger.js` — proof entries become `proof.*` events in `events.jsonl`

### `config-guard.js`
Removed from `hooks.json`. `workflow-enforcer.js` already covers this sentinel-aware. The redundancy was causing incorrect blocks during normal (non-agent-team) usage.

### `proof-ledger.js`
Removed as a separate hook. Functionality merged into `tracking-emitter.js` as `proof.*` events.

### `/deep-research` skill
Writes `.current-context.json` at start: `{ ticket, phase: "research", runSlug: null }`.  
Deletes it on completion.

### `/new-plan` skill
Writes `.current-context.json` at start: `{ ticket, phase: "plan", runSlug: null }`.  
Deletes it on completion.

### `wf-preflight`
Writes `.current-context.json`: `{ ticket, phase: "agent-team", runSlug: null }`.

### `wf-setup`
- Creates `tasks/NNN-slug/` folder
- Moves staged `research/` content into the run folder (snapshot)
- Updates `.current-context.json` with `runSlug`

### `wf-finalize`
1. Reads `events.jsonl` to compile per-agent metrics + timeline
2. Team-lead writes `<run-summary>` prose
3. Writes `tasks/NNN-slug/report.md`
4. Deletes `.current-context.json`
5. Deletes `.workflow-active` sentinel
6. Deletes `.workflow-state/` directory
7. Pushes branch, creates PR (optional)
8. TeamDelete

## Electron App Consumption

### File Watching

Chokidar watching `./progress/` recursively. Two patterns:

- `**/events.jsonl` — tail new lines, parse JSONL, filter `milestone: true` for re-renders
- `**/.current-context.json` — shows active ticket/phase in status bar

### IPC Shape (main → renderer)

```typescript
// Milestone event — triggers panel re-render
ipc.send('workflow:milestone', {
  ticket: 'ES-101',
  run: '001-auth-refactor',
  event: 'agent.spawned',
  agent: 'schema-designer',
  ts: '2026-04-03T10:05:00Z',
  data: {}
})

// Active context changed — updates status bar
ipc.send('workflow:context', {
  ticket: 'ES-101',
  phase: 'agent-team',
  runSlug: '001-auth-refactor'
})

// Permission required — highest priority, opens modal
ipc.send('workflow:permission', {
  ticket: 'ES-101',
  agent: 'schema-designer',
  message: '...'
})
```

### Historical Data

App reads `events.jsonl` directly for analytics and task list views — no IPC needed. Filter by `ticket`, `run`, `agent`, or event type. `report.md` XML tags provide pre-aggregated metrics for completed run views without replaying the full event log.

Archive folder (`./progress/archive/`) watched by the same watcher — historical runs appear automatically, no separate indexing.
